# The exact dependency set the test suite is known to pass on.
#
# A pip CONSTRAINTS file, not a requirements file: it pins versions without
# adding packages, so `pip install -r requirements.txt -c constraints.txt`
# installs the same things it always did, at known versions.
#
# It exists because CI resolved a different set from the development venv
# the first time it ran -- requirements.txt asks for `>=` on everything, so
# "install the dependencies" means "install whatever was newest today".
# What that produced was anyio 4.16 against 4.14 here, starlette 1.10
# against 1.3, fastapi 0.162 against 0.139, and a suite that hung for
# twelve minutes until the job timed out. anyio in particular is the
# library behind how a cancelled httpx request surfaces, which the hub
# reporter's shutdown already had to be written around.
#
# Regenerate deliberately, as an upgrade, not as a drive-by:
#     .venv/Scripts/python.exe -m pip freeze > constraints.txt
# and run the suite before committing the result.
#
# NOTE: requirements.txt itself is still unpinned, so a `pip install` on the
# hub resolves whatever is newest that day. That is a separate decision --
# see the CI section of hub/README.md.
